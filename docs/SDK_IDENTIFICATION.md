# SDK function identification

This is an advisory origin inventory, not a build or compiler policy. It does not claim every SDK function has been identified. Compiler runtime/MSL and third-party middleware are separate categories.

## Results

357 structural candidates: 3 verified origins, 134 strong structural candidates, 220 requiring further review.
196 candidates have a corresponding reconstructed C definition. Some also have assembly definitions in another processor/version.

## Evidence and limitations

Reference assembly comes from pinned pret/pokediamond and pret/pokeheartgold reconstructions. Branch destinations and PC-relative literal addresses are normalized, so even a100% structural similarity is not byte matching. Small or ambiguous routines require manual review. Do not rename functions or select compilers from this file automatically. SDK routines can be originally C or originally assembly; origin alone does not justify assembly acceptance.

Verified origins include OS_Sleep (168-byte C++ reconstruction, integrated using its historical compiler profile) and accepted SDK assembly entries in runtime_support.json. Each verified record retains its proof; structural candidates remain unaccepted.

Full machine-readable evidence: [sdk_function_candidates.json](../config/usa/sdk_function_candidates.json).
